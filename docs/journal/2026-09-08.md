- **~04:00** UX/UI-аудит по запросу: Playwright-скриншоты всех 14 маршрутов
  × 3 ширины (375/768/1440) под реальными демо-логинами каждой роли, не
  макеты. Нашёл и исправил:
  - **Экран сравнения консьержа физически недоступен на планшете
    (768–900px).** `react-resizable-panels` несёт устойчивый hydration
    mismatch на этой странице (SSR/клиент расходятся в инлайн-`style`
    Panel, React помечает «won't be patched up» и не пересчитывает) — в
    диапазоне 768–900px это схлопывало панель `detail` до буквально
    нулевой ширины (замерено `boundingBox()`), а `list` занимала всё.
    Split включён с `lg` (1024px) вместо `md` (768px) — там сумма
    помещается и `detail` получает видимую полосу. ADR не заводил
    отдельно — фикс точечный, причина уже описана в комментарии кода.
  - **Нижняя таб-навигация: `admin` (7 пунктов) не читалась** —
    подписи обрывались на середине слова («Как ...», «Мет...»), у
    `buyer` (6 пунктов) при первой попытке фикса (через `flex-[1_0_72px]`)
    неявно потерялся `min-w-0` на flex-элементе — классический CSS-капкан:
    без него `min-width:auto` для nowrap-текста равен полной ширине
    подписи и `truncate` не срабатывает вообще, элементы наезжали друг на
    друга без пробела. Итоговая пара классов — `min-w-0 flex-[1_0_60px]`
    плюс `overflow-x-auto` на самом `<nav>`: 60px — минимум, при котором
    все 6 пунктов buyer помещаются без скролла; у admin последний пункт
    уезжает за экран, но лента скроллится, а не рассыпается в мусор.
  - **`/buyer/orders/[id]` показывал плейсхолдер-план как настоящий.**
    `intakeRequest()` пишет заглушку `plans` (`kind:'manual', total:0,
    status:'draft'`) для черновика заказа — страница рендерила её
    безусловно по `order.plan &&`, буквально показывая покупателю карточку
    «manual / 0 ₸ / 0 поставщика». Добавил `&& order.plan.status !== 'draft'`.
  - **Склонение «поставщик» было верно только для n=1.** `n === 1 ? 'а' :
    'б'` в двух местах (`/buyer/orders/[id]`, экран сравнения консьержа)
    давало «0 поставщика», «11 поставщик» и т.п. Новый
    `apps/web/app/lib/pluralize.ts` (`pluralizeRu`/`supplierCountLabel`,
    обычные mod10/mod100-правила) — общий, не дублирован по месту находки.
  - **Быстрые действия на `/buyer` ломались на планшете.** `sm:grid-cols-3`
    считает точку по ширине ВСЕГО вьюпорта, не по реальной ширине колонки
    контента внутри сайдбара — на 768px это давало ~156px на плитку,
    заголовок без `truncate` переносился в мешанину из 2-3 строк. Сетка —
    `sm:grid-cols-2 lg:grid-cols-3`, заголовку добавлен `truncate`.
  - **`/buyer/messages` на планшете сжимала тред до ~200px.** Список
    тредов (320px, фиксированный) включался на том же `md`, что и сайдбар
    оболочки (240px) — вместе они почти не оставляли места треду.
    Точка сдвинута на `lg` — до неё страница честно показывает один тред
    на всю ширину (тот же приём, что уже есть у мобильной раскладки), а
    не три колонки без места ни для одной.
  Не чинил (за пределами UI-скоупа, но стоит знать): `on_hold` в
  `packages/engine/order/transition.ts` достижим из `plan_approved` И из
  `disputed`, но единственный путь возврата — в `suppliers_paid` — верно
  для первого случая, ошибочно для второго (реально не проявляется:
  единственный сидовый `on_hold`-заказ пришёл из `plan_approved`, но
  граф это не гарантирует). Сама hydration mismatch у react-resizable-panels
  осталась — сдвиг брейкпоинта обходит её проявление, не устраняет причину.
  `pnpm lint/typecheck/test/build` — зелёные после всех правок.
