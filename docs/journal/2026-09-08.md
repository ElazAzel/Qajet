Реальный баг найден при первой живой проверке: `matchNomenclature` сравнивает ВСЮ введённую строку с коротким названием каталога («120 футболок с логотипом до 20 октября» против «Футболка с логотипом») — триграммы+Дамерау-Левенштейн закономерно давали заниженное сходство (51%, ниже порога 0.72) просто из-за длины строки, не из-за реального несовпадения. Добавлена локальная (не в движке — только для этого одного вызова) очистка текста от количества/срока/валюты перед сравнением номенклатуры — подняло схожесть до 85%. Второй баг, найденный тут же: регэксп для очистки использовал `\b` вокруг кириллических слов — в JS `\b` определена через `\w` (`[A-Za-z0-9_]`), кириллица туда не входит, поэтому границы слов вокруг кириллицы просто не срабатывают (цифры очищались, слова типа «до»/«к»/месяцы — нет). Заменено на явные lookaround (`(?<![a-zа-яё])...(?![a-zа-яё])`). Подтверждено живым Playwright-прогоном под `buyer@demo.qajet.kz`: разбор → превью 85% → подтверждение → позиция и дата добавлены в форму. `pnpm lint/typecheck/test/build` — зелёные.
