# Базовая линия и итоги: доказательства и их границы

Локальные тесты никогда не доказывают поведение провайдера, деплоя, CI или
продакшена. Ниже — что проверено, чем и что остаётся вне ветки.

## Словарь

- `CONFIRMED` — проверено по названному артефакту или выводу команды.
- `REPRODUCED` — исполняемый сценарий запущен и показал поведение.
- `NOT REPRODUCED` — релевантный сценарий запущен и поведение не подтвердил.
- `NOT RUN` — проверка сознательно не выполнялась; это не доказательство.
- `ASSUMPTION` — вход для планирования, никогда не доказательство.

## Локальная замена CI (с 2026-09-20)

GitHub Actions на ветке `refactor/pilot-readiness` не выполняет ни одного шага:
задачи не стартуют из-за биллинга аккаунта. Поэтому появился `pnpm ci:local`
(`tools/ci/run-local.mjs`) — он запускает тот же список задач теми же командами
и пишет `gates.local.json` с пометкой `source: local`.

Это **не** доказательство CI. Локальный прогон даёт `passed-local`; ворота CI,
провайдера, деплоя и production остаются `NOT RUN`, пока не выполнены
по-настоящему. Файл `gates.json`, который создаёт CI, скрипт намеренно не пишет,
а `gates.local.json` не коммитится.

Последний полный прогон: коммит `ffcd756`, все семь ворот PASS, 790 с.
После него локальная сборка на машине владельца перестала работать —
`next build` падает с `EBUSY` при удалении устаревшей копии питч-PDF, которую
держат Defender и индексатор Windows. Сам PDF из репозитория убран (коммит
`d2002e7`), но уже заблокированная копия требует перезагрузки или исключения
каталога в Defender. Из-за этого коммиты после `ffcd756` проверены только по
тем воротам, которым сборка не нужна: линт, типы, модульные тесты, RLS на
реальной PostgreSQL и свежесть индекса.
