# ADR-0004 — RAG фазы 0: FTS5 сейчас, векторный слой отдельным заходом

Дата: 2026-09-06
Статус: принято, частично

## Контекст

В одобренном плане реализации RAG-система описана как гибридный поиск:
FTS5 (BM25) + `sqlite-vec` по локальным эмбеддингам через
`@huggingface/transformers`, без единого внешнего API-ключа.

## Решение

В этой сборке реализована только часть FTS5. Векторный слой сознательно
отложен, а не упущен по недосмотру — по трём причинам:

1. **Вес и риск зависимости.** `@huggingface/transformers` тянет ONNX
   Runtime и модель эмбеддингов (десятки МБ, скачивается при первом
   использовании) — это заметно увеличивает поверхность отказа
   инструмента разработки в первой же фазе, когда важнее, чтобы каркас
   проекта был безусловно надёжен.
2. **`sqlite-vec` как загружаемое расширение** через `node:sqlite`
   (`allowExtension` + `loadExtension`) — рабочий путь, но непроверенный
   на этой машине на дату решения; сначала стоило убедиться, что базовый
   FTS5-индекс через `node:sqlite` (тоже experimental API Node) сам по
   себе стабилен — что и было сделано и подтверждено (`pnpm rag:sync`,
   `pnpm rag:search`, `pnpm rag:check` работают).
3. **Отдача уже есть без векторного слоя.** Ключевой BM25-поиск по
   `agents.md`, ADR и журналу — то, ради чего вообще заводится RAG на
   этом этапе («чтобы ничего не забыть») — уже полноценно работает.
   Семантический поиск добавляет recall на перефразированных запросах,
   но не является условием полезности инструмента.

## Что сделано

- `tools/rag/src/db.ts` — индекс на `node:sqlite` (встроенный, без
  нативной компиляции), таблица `documents` + внешняя FTS5-таблица
  `documents_fts` с триггерами синхронизации.
- `tools/rag/src/corpus.ts` — нарезка `agents.md` по заголовкам ## и ###,
  плюс ADR (`docs/decisions/`), журнал (`docs/journal/`) и сгенерированное
  состояние (`docs/state/`).
- `tools/rag/src/state.ts` — `docs/state/{routes,packages,ledger}.md`
  генерируются из фактической файловой системы репозитория, не пишутся
  руками. `ledger.md` — чек-лист фаз с автоматической отметкой по наличию
  файлов-свидетелей.
- CLI: `pnpm rag:sync` (перегенерировать state + переиндексировать),
  `pnpm rag:search <запрос>`, `pnpm rag:check` (индекс не отстал от кода —
  для CI), `pnpm rag:log <текст>` (запись в журнал сессии).
- MCP-сервер `tools/rag/src/mcp.ts`, подключённый в `.mcp.json` —
  инструменты `qajet_search`, `qajet_ledger`, `qajet_log` доступны прямо
  из сессии Claude Code.

## Что осталось (отслеживается в docs/state/ledger.md автоматически)

Векторный слой — `sqlite-vec` через `db.loadExtension()` +
`@huggingface/transformers` для эмбеддингов RU/KZ/EN, слияние с BM25 через
Reciprocal Rank Fusion — реализуется отдельным заходом, когда в корпусе
станет достаточно свободного текста (после фазы 2+, когда появятся
`explanation`-структуры движка), чтобы семантический поиск был кому ловить.
