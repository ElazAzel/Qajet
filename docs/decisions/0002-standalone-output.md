# ADR-0002 — `output: 'standalone'` и отказ от рантайм-зависимостей платформы

Дата: 2026-09-06
Статус: принято

## Контекст

MVP разворачивается на GitHub + Vercel, но пользователь прямо сказал, что
дальше перенесёт всё на собственные облачные серверы. Переезд не должен
требовать переписывания приложения.

## Решение

- `next.config.ts`: `output: 'standalone'` — сборка даёт самодостаточный
  Node-сервер, который запускается `node server.js` где угодно, без Vercel
  Runtime.
- Ни одна рантайм-зависимость `@vercel/*` не добавляется в `apps/web`.
  Аналитика, edge-конфигурация и подобное — либо не используются, либо
  берутся через открытые стандарты (Web Fetch API, стандартные Route
  Handlers), а не через платформенные SDK.
- Фоновые задачи (`recalibrate()` по крону, фаза 6) реализуются через
  `pg_cron` в самом Postgres, а не через `vercel.json` cron-задания —
  крон переезжает вместе с базой данных, а не остаётся в Vercel.
- Файловое хранилище — через собственный интерфейс с двумя реализациями:
  Supabase Storage (MVP) и S3-совместимая (перенос).

## Последствия

Deploy на Vercel остаётся стандартным (`git push` → превью), но ничего в
коде не привязано к тому, что это именно Vercel. Runbook переезда —
фаза 8 плана реализации.
