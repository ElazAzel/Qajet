# ADR-0003 — Сборка `apps/web` на webpack, а не на Turbopack по умолчанию

Дата: 2026-09-06
Статус: принято, временно

## Контекст

Next.js 16 включает Turbopack по умолчанию и для `dev`, и для `build`.
`@serwist/next` (пакет для PWA/офлайн-слоя, ADR не менялся — выбор сделан
по агентс.md §2) внедряет service worker через собственную конфигурацию
webpack. При сборке под Turbopack Next 16 обнаруживает чужой webpack-конфиг
без явного `turbopack: {}` и **падает** с ошибкой:

```
ERROR: This build is using Turbopack, with a `webpack` config and no
`turbopack` config. This may be a mistake.
```

Это не ошибка в нашем коде, а известный, открытый разрыв экосистемы:
Serwist сам предупреждает об этом при сборке и ссылается на
`github.com/serwist/serwist/issues/54`. У проблемы три официальных обхода:

1. Собирать явно на webpack (`next build --webpack`).
2. Перейти на `@serwist/turbopack` — **экспериментальный** пакет, который
   не встраивается в бандлер вовсе: он отдаёт `sw.js` через динамический
   Route Handler, компилируя его esbuild'ом на лету (в рантайме, с кэшем по
   хешу исходника), и требует `@serwist/window`/`SerwistProvider` вместо
   автоматической регистрации.
3. Замолчать предупреждение, задав пустой `turbopack: {}` — это НЕ решает
   проблему, а прячет её: конфигурация Serwist для генерации service worker
   при этом просто не применяется, и офлайн-слой перестаёт собираться молча.

## Решение

Собирать `apps/web` явно на webpack: `next dev --webpack`,
`next build --webpack` (`apps/web/package.json`). Вариант 2 отклонён на
этом этапе — офлайн-режим прямо требуется спекой (`agents.md` §2, §13:
«на сцене Wi-Fi всегда падает») и обязан быть надёжным с первого дня,
а рантайм-компиляция service worker через esbuild — заметно более новый и
менее обкатанный путь для этой же задачи. Вариант 3 отклонён как маскировка
бага, а не решение.

## Последствия

- Turbopack не используется для `apps/web`, пока `serwist/serwist#54` не
  закроется или `@serwist/turbopack` не выйдет из экспериментального
  статуса. Это единственное отступление от «Turbopack по умолчанию» в
  проекте — остальной стек (`packages/ui`, движок, тесты) от бандлера
  Next.js не зависит вовсе.
- Пересмотреть при следующем крупном обновлении Serwist или Next.js —
  отметка в `docs/journal/`, когда это будет проверено повторно.
