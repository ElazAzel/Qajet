# QAJET

Внешний отдел закупок для HR- и маркетинг-команд в Алматы: мерч, корпоративные
наборы, полиграфия. QAJET сравнивает не отдельные строки прайса, а целые
исполнимые варианты решения закупочной задачи, ведёт заказ до приёмки и
закрывающих документов.

Полная спецификация продукта — [`agents.md`](./agents.md). Она источник истины
для этого репозитория: любое изменение логики заказов, оплат, ролей или
поставщиков сверяется с ней в первую очередь. Правки в неё вносятся вместе с
кодом, а не постфактум.

## Честный статус

Проект в разработке. Ниже — что реально работает сейчас, без округления в
большую сторону:

- Каркас монорепо, дизайн-токены и три разные оболочки ролей (покупатель,
  консьерж, поставщик) — кликабельные пустые маршруты.
- PWA: офлайн-оболочка, манифест, установка на десктоп и телефон.
- RAG-инструмент разработки (`tools/rag`) — поиск по спецификации, ADR и
  журналу, доступный как MCP-сервер прямо в сессии.
- Движок расчётов, схема данных, сид и сами рабочие сценарии по ролям —
  ещё не реализованы. Актуальный чек-лист фаз — [`docs/state/ledger.md`](./docs/state/ledger.md)
  (генерируется автоматически, не редактируется руками).

## Быстрый старт

```bash
pnpm install
pnpm dev            # apps/web на localhost:3000
```

```bash
pnpm lint           # Biome
pnpm typecheck      # tsc по всем пакетам монорепо (Turborepo)
pnpm test           # Vitest
pnpm --filter @qajet/web build   # production-сборка Next.js
```

```bash
pnpm rag:sync              # перегенерировать docs/state/ и переиндексировать корпус
pnpm rag:search <запрос>   # поиск по agents.md, ADR, журналу
pnpm rag:check             # индекс не отстал от кода (используется в CI)
pnpm rag:log <текст>       # запись в журнал сессии
```

## Структура репозитория

```
apps/
  web/          Next.js 16 — единственное приложение
packages/
  ui/           дизайн-система: токены, моушн-система, оболочки ролей
  engine/       (фаза 2) детерминированные алгоритмы, ноль внешних вызовов
  db/           (фаза 1) Drizzle: схема, RLS-политики, миграции, сид
  contracts/    (фаза 1+) zod-схемы, общие для сервера и клиента
  pd/           единственная точка доступа к персональным данным + maskPII()
tools/
  rag/          корпус знаний + индекс + MCP-сервер
docs/
  decisions/    ADR — инженерные решения с обоснованием
  journal/      журнал сессий разработки
  state/        генерируется `pnpm rag:sync`, не редактируется руками
```

## Технические решения

Версии стека, отклонения от «последней версии» и почему, а также
архитектурные решения по переносимости — в [`docs/decisions/`](./docs/decisions/):

- [ADR-0001](./docs/decisions/0001-stack-versions.md) — версии стека
- [ADR-0002](./docs/decisions/0002-standalone-output.md) — `output: 'standalone'`, независимость от Vercel в рантайме
- [ADR-0003](./docs/decisions/0003-serwist-webpack-build.md) — сборка на webpack, не на Turbopack (известный разрыв Serwist ↔ Turbopack)
- [ADR-0004](./docs/decisions/0004-rag-fts-first.md) — RAG: FTS5 сейчас, векторный слой отдельным заходом
- [ADR-0005](./docs/decisions/0005-pd-backend-abstraction.md) — `packages/pd`: конфигурируемый бэкенд для персональных данных

## Известные ограничения

- **Персональные данные.** Supabase-проект MVP размещён в `us-east-1`.
  `agents.md` §11.1 требует хранения персональных данных казахстанских
  резидентов в ДЦ на территории РК — для прототипа это допустимо, для
  платного пилота нет. `packages/pd` — единственная точка доступа к
  персональным данным (имя, email, адрес доставки) с конфигурируемым
  бэкендом (см. [ADR-0005](./docs/decisions/0005-pd-backend-abstraction.md));
  сегодня бэкенд — та же Supabase-сессия, переезд на казахстанский ДЦ —
  замена одной реализации, а не рефакторинг apps/web.
- **Маскирование перед LLM.** `maskPII()`/`unmaskPII()` (`packages/pd`,
  agents.md §11.2) готовы и покрыты тестами, но вызывать их пока некому:
  `FEATURE_LLM_ASSIST=false`, вызовов внешних моделей в рантайме нет
  (agents.md §2). Тип `MaskedPayload` уже существует для будущего
  intake-enhancer'а — функция, которая его вызовет, физически не сможет
  принять немаскированный текст.
- **Учёт времени.** `time_entries` в схеме есть, но автотаймер консьержа
  (agents.md §9: старт по стадии, пауза после 60с бездействия) не
  подключён к UI — таблица пустая. `/metrics` честно показывает «часы на
  заказ» как «нет данных» вместо фиктивного числа.
- **Мобильная оболочка (фаза 7).** Capacitor не собирает Next.js с Server
  Actions в статику — мобильное приложение будет webview на развёрнутый
  адрес с нативными плагинами (push, haptics, камера), не полностью
  офлайновым нативным клиентом.

## Переезд на собственные серверы

MVP развёрнут на GitHub + Vercel. Приложение с первого коммита не имеет
рантайм-зависимостей от платформы (`output: 'standalone'`, ADR-0002) —
переезд на собственную инфраструктуру описывается в фазе 8 плана и требует
переноса Postgres, файлового хранилища и переменных окружения, а не
переписывания кода.
