# QAJET Mobile (Capacitor 8)

Сценарий поставщика первичен (план, §"Оболочка мобильного"). Как и
`apps/desktop`, это не отдельный фронтенд: `capacitor.config.ts` →
`server.url` открывает боевой адрес Vercel в системном WebView, тем же
кодом `apps/web`, что и обычный мобильный браузер.

**Честно, прямым текстом (см. также README.md корня репозитория,
раздел «Известные ограничения»):** Capacitor не умеет собрать Next.js
со Server Actions в статику — `webDir: 'www'` содержит только заглушку
на случай, если системный WebView не достучится до сети при старте, а
не бандл приложения. Это webview-обёртка с нативными плагинами, а не
полностью офлайновое нативное приложение.

## Что даёт обёртка поверх браузера

Плагины ниже вызываются из общего кода `apps/web` через
`apps/web/app/lib/native-bridge.ts` — там же комментарий, что каждая
функция проверяет `Capacitor.isNativePlatform()` и ничего не делает в
обычном браузере:

- **push-уведомления** (`@capacitor/push-notifications`) — запрос
  разрешения и регистрация при старте приложения (`initNativeApp()`).
  Токен устройства пока только логируется: сервер не умеет его принимать
  и хранить (нет эндпоинта/таблицы) — `/admin/outbox` (agents.md §9)
  сегодня шлёт в почту/outbox-таблицу, не push. Открытый пункт.
- **haptics** (`@capacitor/haptics`) — тактильный отклик на «Утвердить
  план» / «Принять поставку» (`_order-actions.tsx`).
- **шаринг** (`@capacitor/share`) — кнопка «Поделиться» на
  `/buyer/orders/[id]`; работает и в обычном браузере (пакет несёт
  веб-реализацию поверх `navigator.share`), не только в приложении.
- **камера** (`@capacitor/android`/`@capacitor/ios` тянут её транзитивно
  как часть стандартного набора) заложена в план («съёмка бумажного КП»,
  agents.md фаза 7), но НЕ подключена ни к одной форме в этой сессии —
  в схеме БД нет поля/таблицы для вложений к `quotes`, а вызывать камеру
  и никуда не сохранять результат — это ровно тот полуготовый код,
  которого проект избегает. Подключать вместе со схемой хранения файлов
  (Supabase Storage/S3, уже заложено в фазе 8 `packages/pd`-паттерном).

## Локальная сборка

Нативные проекты `android/` и `ios/` не сгенерированы и не закоммичены —
это одноразовый шаг, который выполняется на машине с установленными
Android Studio / Xcode, отсутствующими в песочнице разработки этой сессии:

```
pnpm --filter @qajet/mobile add:android   # один раз, требует Android SDK
pnpm --filter @qajet/mobile add:ios       # один раз, требует Xcode (только macOS)
pnpm --filter @qajet/mobile sync          # после каждого изменения capacitor.config.ts
pnpm --filter @qajet/mobile open:android
pnpm --filter @qajet/mobile open:ios
```

Иконки те же, что у `apps/desktop` — `tools/branding/icon-512.png`,
`pnpm --filter @qajet/desktop icon` уже сгенерировал и Android/iOS-варианты
(`apps/desktop/src-tauri/icons/{android,ios}/`) тем же прогоном
`tauri icon`; при `cap add` их достаточно скопировать в
`android/app/src/main/res` / `ios/App/App/Assets.xcassets`, а не
перегенерировать заново.

## Двухступенчатый ответ поставщика без входа

Указанный в agents.md §10 сценарий (ответ на RFQ по защищённой ссылке без
входа, с телефона) работает в обычном мобильном браузере уже сегодня и не
требует этой обёртки — README корня репозитория честно фиксирует, что
живая реализация пока идёт через авторизованный дашборд
(`/supplier/rfq/[id]`), а не через ссылку без входа; это ограничение
существующего кода, а не обёртки.
